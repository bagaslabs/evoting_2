## Design Specificity Verdict

**LLM assessment:** The "Trusted Ballot Desk" world is real: paper-green ground, evergreen authority, one amber stamp, Bricolage display type, and the notched ballot artifact. The landing page and public results feel authored for a campus election rather than a generic SaaS template. The kiosk and admin surfaces drift toward category-generic (split slogan + card; stacked panels). The biggest specificity gap is that the signature ballot card appears only on the landing hero — the actual voting screen uses plain candidate cards, so the system's best idea is decoration instead of the instrument. The admin could belong to almost any internal tool.

**Deterministic scan:** 55 findings in `src/index.css` — 2 warnings, 53 advisories.
- 2 × `overused-font` (Plus Jakarta Sans, `src/index.css:1`, `:4`). The font is a deliberate DESIGN.md commitment; treat as advisory, not a defect to fix.
- 34 × `design-system-font-size`. Real scale drift: the CSS uses an ad-hoc ramp (0.7, 0.78, 0.86, 0.98, 1.35, 1.6, 1.72, 2.7rem) instead of documented steps. Low user impact; it does mean DESIGN.md is not the actual source of truth.
- 15 × `design-system-color` (e.g. `#8f2b22`, `#cfe0d8`, `#3fa985`). Mostly tonal variants for info/success notices, badges, and the results gradient that the palette never documented. Absorb them into DESIGN.md rather than removing them.
- 4 × `design-system-radius`: `8px` at `src/index.css:310` is real drift (`btn-sm` uses 8px while the DESIGN.md component spec says 9px); `14px` and `18px` are documented in DESIGN.md prose (nested cards 12–14px; ballot/dialog 18px) but missing from the `rounded` token table, so those are documentation conflicts, not code errors.

**Visual overlays:** Not available. Screenshots were captured through headless Chrome via CDP; there is no interactive browser tab, so no user-visible overlay is claimed.

## Overall Impression

Strong visual identity and genuinely careful destructive-action UX. The kiosk flow's biggest failure is that the decorative slogan outranks the task, and a voter has no clean way to correct an identity mistake. The results page reports a tally but not an outcome. The single biggest opportunity is to make the ballot card the instrument of the vote and let the action card lead the kiosk screen.

## What's Working

1. The ballot artifact, paper palette, and amber stamp form a coherent, non-generic election identity that survives at both 1440 and 390. The hero reads as a printed polling slip, not a SaaS card.
2. Voting is two-step (select candidate → confirm), and the confirmation restates both the voter's name and the candidate's name. That is the right pattern for an irreversible action.
3. Admin destructive paths (force release, cancel assignment) collect a reason and land in the audit log. That is audience-appropriate trust design for an organizer under pressure.

## Priority Issues

### [P1] The kiosk action is visually subordinate to a slogan
- **Why it matters:** At 1440 the 4.8rem "Suara Anda, masa depan angkatan." is the focal point while the NIM field and action card sit in a 0.8fr column on the right. A first-time voter scans the slogan before the task; at a queue, every extra second multiplies. Operate mode should make the next action unmistakable.
- **Fix:** Give the action card the dominant column during `assigned`/`verified`/`voting` stages (e.g. 0.8fr copy / 1.2fr action), promote the stage title to the largest type, and reduce the slogan to a small section marker. Keep the display-scale slogan only for idle/waiting states.
- **Suggested command:** `/impeccable layout`

### [P1] No voter recovery after NIM verification
- **Why it matters:** Once biodata is shown there is no "Batal / bukan saya". The only exit is "Ganti identitas perangkat", which deletes the device token from localStorage and sends the device back to token entry — a queue-stopping failure at the highest-anxiety moment.
- **Fix:** Add a secondary "Batal, bukan saya" action on the biodata stage that returns to `assigned` without clearing the token (the admin can cancel the server-side assignment). Keep "Ganti identitas perangkat" for panitia, confirm it, and stop deleting the token by default.
- **Suggested command:** `/impeccable harden`

### [P1] The vote confirmation autofocuses the irreversible action
- **Why it matters:** `ConfirmDialog.tsx:42` puts `data-autofocus` on "Kirim suara". Pressing Enter after the dialog opens casts the vote before the voter has read the summary. On a kiosk with an external keyboard or an Enter-happy user, this is a wrong-vote path that cannot be undone.
- **Fix:** Autofocus "Batal" or the dialog heading, require an explicit click/Tab to reach "Kirim suara", and keep the dialog's existing Escape/backdrop cancel.
- **Suggested command:** `/impeccable harden`

### [P2] The results page reports a tally, not an outcome
- **Why it matters:** There is no winner/rank callout, no "final / published at" timestamp, no eligible-voter denominator ("1 dari 128 pemilih"), and "0.78%" uses a dot although `id-ID` expects a comma. A public result that does not declare its own status undermines the product's stated "trust is visible" principle.
- **Fix:** Add a result header with election state and publication time, highlight the leading candidate, show the turnout denominator, and format all numbers through `Intl.NumberFormat("id-ID")`.
- **Suggested command:** `/impeccable clarify`

### [P2] Admin is one undifferentiated eight-panel stack
- **Why it matters:** Devices, assignments, an eight-column roster, import, per-candidate edit forms, audit, and password all compete in one scroll. Destructive controls sit beside daily ones, "Assignment aktif / eligible / Roster / Realtime" break the Indonesian voice, and disabled controls explain themselves only through `title`.
- **Fix:** Add in-page section navigation or tabs (Perangkat / Pemilih / Kandidat / Audit), move rare and destructive actions into row menus, replace jargon with "Penugasan", "berhak memilih", "Daftar pemilih", "pembaruan langsung", and render visible reasons for disabled controls.
- **Suggested command:** `/impeccable layout`

## Persona Red Flags

**Jordan (first-timer voter at the kiosk):** The first thing he reads is a slogan, not "Masukkan NIM". "Menyiapkan antrean…" gives no expectation of wait or instruction to call panitia. After verifying, there is no "bukan saya". With five or more candidates the ballot becomes a wall of equal cards.

**Sam (accessibility-dependent):** Muted text on the paper ground is 4.38:1 (`#64736c` on `#eef1ec`), failing AA for footer text and the hero footnote. Disabled delete/reorder controls rely on `title`, which is unreliable for keyboard/screen-reader users. The thank-you stage auto-resets after five seconds with no announced countdown or extension. At 390px the device brand wraps to three lines.

**Alex (power-user admin):** No keyboard shortcuts and no bulk device assignment; devices must be assigned one row at a time. Every candidate renders a full edit form, so scanning and batch editing are slow. The eight-panel scroll forces repeated searching between devices and audit.

## Minor Observations

- At 390px the device header brand wraps to three lines (E- / Voting / Teknik Elektro) because the connection text competes for width; stack the connection line under the brand.
- At ≤420px the public nav hides "Hasil pemilihan" but keeps "Admin" (`src/index.css:1610`) — the public destination is the one that should survive.
- Ballot notches are flat `--paper` discs over a gradient, so they read as mismatched pale circles; use a mask or match the local gradient.
- The audit log renders raw JSON (`{"reason":"..."}`) in `<code>`; humanize the details column.
- The candidate form preview is 16:9 while the device card image is a fixed 180px height, so the preview does not match the ballot.
- "Tutup pemilihan" has no confirmation while lower-risk voter deletion does.
- At 390px the results "Muat ulang" button stacks under the section marker instead of aligning with it.
- 34 font-size literals sit off the DESIGN.md ramp; either adopt a token scale or update DESIGN.md to match reality.
